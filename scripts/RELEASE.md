# Shipping an Android release

## Build

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build-release-aab.ps1
```

Output: `hooked\content\hooked-release.aab` — that's the file Play wants.
First run takes ~17 minutes because Gradle pulls the NDK; later runs are far
quicker. The script needs the JDK and Android SDK that
`hooked\scripts\local-android-build.ps1` installs, so run that once first on a
fresh machine.

## Signing

`android/` is gitignored and regenerated by `expo prebuild` on every build, so
the signing config can't be committed — the script re-applies it each run and
**fails the build** if the patch doesn't take. That matters: the Expo template
points the release build at `debug.keystore`, and a debug-signed bundle looks
completely normal right up until Play rejects it.

The upload key lives outside the repo, at:

```
%USERPROFILE%\.keystores\hooked-upload.jks
%USERPROFILE%\.keystores\hooked-upload.pw     <- store + key password
%USERPROFILE%\.keystores\hooked-upload.README.txt
```

**Back that folder up somewhere off this machine.** Google Play signs what users
install with its own key; this one signs the *upload*. If it's lost you can't
publish an update until Google approves an upload-key reset.

Certificate SHA-256 (what Play displays under App integrity):

```
11:80:7D:9B:81:C1:90:89:F1:0A:69:92:73:5C:1B:1B:08:CF:E1:0E:EA:5D:25:18:B4:B4:B5:BF:33:28:3C:D6
```

To check any bundle before uploading:

```powershell
& "$env:USERPROFILE\.jdks\jdk-17*\bin\jarsigner.exe" -verify -verbose:summary -certs <file>.aab
```

`CN=hooked` is right. `CN=Android Debug` means it will be rejected.

## Versioning

`app.json` holds `version` and `android.versionCode`. Play refuses a versionCode
it has already seen, so bump it for every upload. `eas.json` sets
`appVersionSource: remote`, which only applies to EAS builds — a local build uses
whatever is in `app.json`.

Current: `1.0.2`, versionCode `3`, package `com.minus.hooked`, targetSdk 36.
